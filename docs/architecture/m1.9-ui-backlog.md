# M1.9 backlog — hosted execution UI

> Ordered implementation record for [D-2026-08-31-2](../spec/decisions.md)
> and [`ui.md`](../spec/ui.md). M1.9 replaces the old one-line `--watch`
> placeholder with the agreed `--ui` surface. Each gate must keep ordinary
> non-UI execution, package identity and causal traces byte-identical.

**Checkpoint 2026-08-31:** U0–U4 and the non-visual U6 gates are executable.
U5 now has a seed-style layered SVG projection, journal-derived per-edge
envelope counts, exact last-boundary/transaction-owner activity and
click/keyboard access to source-faithful Node and Graph definitions under the
CLI protocol regression. The refinement pass adds frame-owned Graph/App ports,
a compact system-themed sticky transport, separate `META`/`DATA` inspection,
and a resolved-type editor for the next pre-admission Lab injection without
adding a second ingress path. A correctness refinement freezes hosted logical
time throughout debugger suspension, gives lifecycle records their exact
trigger and human label, and uses Graph/Node selection as one disposable
filter across the related history, instance, exchange and cost panels.
A direct headless-Chrome pass now covers pointer and keyboard definition
selection, refresh persistence and the responsive stacked inspector. The
complete browser control/reconnection/fault pass remains open because the
reference host's bundled browser controller has a version mismatch. See the
[implementation report](m1.9-ui-exit-report.md); the complete exit statement
is not claimed until that qualification closes.

## Exit statement

M1.9 is closed when one optional hosted image serves a capability-protected
loopback page for `run` and `simulate`; every session starts paused; one
control transaction advances exactly one VM transaction in `run`; the primary
simulation step advances exactly one authored action or one VM transaction,
never both; Calls reach a safe pause without suppressing their typed outcomes;
Sessions stay open under their existing bounds; simulations also expose both
boundaries separately; and topology, structured redacted payload/state,
retained history and the existing exact `CostReport` remain inspectable after
completion without becoming execution authority.

## U0 — decision and dependency boundary

- Freeze the command, control-state, safe-pause, read-model and privacy rules.
- Add an independent `hosted-ui` static capability. A reduced build must not
  link Hyper, Tokio, OS randomness or UI assets.
- Reuse the pinned Hyper/Tokio HTTP/1.1 server pieces. Add only an optional,
  direct OS-randomness dependency for the control capability; record version,
  MSRV, licence, transitive delta and removal seam.
- Refuse `--ui`, `--ui-port`, duplicate options and unavailable-build use by
  exact CLI diagnostics.

Exit: docs agree, reduced/full feature checks prove the boundary, and no
identity bytes move.

## U1 — secure embedded server

- Bind `127.0.0.1:0` or the explicit non-zero port before graph execution.
- Generate one unpredictable capability before serving; require it for page,
  snapshot, SSE and control requests.
- Embed one self-contained HTML/CSS/JS page; no npm or filesystem dependency.
- Implement one-controller/many-observer ownership with explicit takeover.
- Keep command and event lanes bounded or reconstructable; a browser cannot
  block the execution thread.

Exit: unauthorized/cross-origin-shaped requests, stale controllers, occupied
ports, disconnects and slow clients are tested; the served assets contain no
runtime token or user payload.

## U2 — common execution controller and `run`

- Introduce `Paused | Running | PauseRequested | Faulted | Completed` outside
  the semantic core; every UI run starts paused.
- Refactor the hosted runner from unbounded drain rounds to transaction
  boundaries when UI is active. Non-UI execution keeps its current fast path.
- Stop new admissions on pause request, finish already-open outbound Calls to
  retained completions, leave Session transports alive, and stop before
  consuming those completions.
- Freeze the hosted wall-to-logical mapping while paused or waiting for a Call
  safe point; resuming must not spend debugger time from semantic budgets.
- Expose `Resume`, `Pause`, `Step`, safe `Retry step`, `Run to completion` and
  `Close`; never expose real-run reset.
- Report transaction faults with causal context, redacted structure and the
  no-commit invariant; distinguish non-retryable boundary failure after prior
  commits.

Exit: model-check command/call-response races; one click commits at most one
VM transaction; a paused run starts no effect without its journal open; and
ordinary `run` output remains unchanged without `--ui`.

## U3 — interactive Lab

- Refactor one scenario into an explicit session owning VM, journal, scripted
  Drivers, virtual clock, observation window and failures.
- Preserve the existing batch runner as a consumer of that session API.
- Expose scenario selection/reset, next action, next transaction, run until
  assertion and run to completion.
- At a quiescent next-`inject` boundary, expose one typed DATA draft. Validate
  every replacement against the resolved App input before the ordinary action
  admits it; reset restores source and no committed envelope is editable.
- Keep golden comparison/blessing in the CLI authority, never in browser
  state.

Exit: interactive and batch execution of the same scenarios produce identical
reports, records and golden traces; reset shares no state.

## U4 — journal-derived view

- Publish validated topology and a revisioned snapshot derived from the
  journal, VM inspection seam and existing CostReport.
- Render every already-materialized DATA root, including unclassified scalars,
  with `kind`, `materialized` and `content`; keep unmaterialized encoded roots
  as representation/size summaries without forcing decode. State remains
  structured-only.
- Redact sensitive/personal paths before JSON construction and never render a
  secret path.
- Keep every in-memory record addressable while browser tables virtualize.

Exit: source→UI and replay→UI snapshots agree; policy sabotage refuses; cost
rows preserve currency/basis/unpriced; an empty policy pays no schema walk.

## U5 — pedagogical page

- Draw the static topology with live Node/edge activity. The landed read model
  reconstructs cumulative edge counts from exact route facts, distinguishes a
  Lab action from a Node transaction, and exposes lifecycle transactions
  rather than visually jumping over them.
- Render the validated owner tree as a compound graph: `App` visibly contains
  direct Nodes and recursively nested Graph frames. Compact cards retain only
  name, NodeType and NodeAspects; white input disks and black output disks own
  the exact edge attachment points, including ports on every Graph frame. No
  dotted-path parsing may invent scope.
- Make every source-backed Graph and Node selectable by pointer and keyboard;
  show its exact declaration, including ports, attributes, handlers and
  guards, from a compiler side table which carries no plan authority.
- Present causal history, instances/lifecycle, Calls/Sessions, structured
  DATA/state and CostReport in distinct, linked panels. The active envelope
  panel names `META` and `DATA` separately and distinguishes a pre-admission
  draft from an immutable admitted envelope.
- Give lifecycle transactions their exact `l:*` trigger and a human verb;
  Graph/Node selection filters every linked panel without truncating the
  retained authority.
- Keep one compact sticky `Rastok UI` bar with a prominent execution-mode
  badge, labelled icon controls and automatic light/dark colors. Status and
  diagnostics remain; generic usage instructions do not occupy the page.
- Make execution state, outstanding Calls, scenario action and next legal
  commands obvious without requiring knowledge of journal internals.
- Preserve keyboard navigation, readable contrast, responsive layout and
  useful empty/fault/completed states.

Exit: browser-level hermetic probes exercise initial pause, stepping,
takeover, reconnection, redaction, fault help, reset and post-completion
inspection.
