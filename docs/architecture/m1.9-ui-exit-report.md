## Result protected

`run` and `simulate` may now be inspected without creating a second runtime,
journal or accounting authority. A UI session starts before the first
semantic transaction in `Paused`; one run `Step in` executes at most one
existing VM transaction, while one simulation `Step in` advances one authored
action or one ready transaction, never both. A manual boundary may stop with a
Call visibly open; only an explicit Pause from Running waits until that Call's
terminal outcome is retained. A Session remains open behind its existing
bounds. Hosted suspension is subtracted from the
wall-to-logical mapping, so inspecting a paused run consumes no timeout,
lifetime or delayed-Loop budget. Non-UI execution takes its previous fast path
unchanged.

Every exact read-model frame is retained under `(branch, B)` before the replaceable
live notification is published. `A`, `B` and `R` separately identify scenario
actions, debugger boundaries and causal records. A real run can show any past
frame while the live machine continues, but cannot execute from history. A
simulation can rebuild a fresh world through a chosen boundary, prove exact
agreement against the retained journal/VM/Lab checkpoint and continue on a new
branch without truncating its source. Play walks the retained boundaries at a
readable cadence; Continue remains the explicit instant path.

The feature is static and optional:

```text
minimal / embedded image          hosted image + hosted-ui
          │                                  │
          └──── same v15 plan + VM ──────────┘
                          │
                journal / inspection / CostReport
                          │
                   disposable UI snapshot
```

## Surface and security

- `rastok run … --ui [--ui-port PORT]` and
  `rastok simulate … --ui [--ui-port PORT]` are the only admitted commands;
  `check --ui`, duplicate flags, a zero/invalid port, `--ui-port` alone and a
  binary without `hosted-ui` refuse by exact diagnostic.
- The server binds only `127.0.0.1`; port zero asks the OS, while an occupied
  requested port refuses before graph execution.
- One 256-bit capability is minted from the OS and required on the document,
  assets, snapshot, SSE and control paths. It moves from the initial URL into
  an HTTP-only same-site cookie and never enters an asset or response body.
- Mutating requests additionally require the exact same origin and one
  controller id. One controller wins; an explicit takeover invalidates stale
  commands. Other authorized tabs remain observers.
- Command, newest-snapshot and SSE lanes are bounded. Browser loss, a slow
  reader or an absent page cannot block the execution thread.
- Embedded HTML/CSS/JavaScript has no npm or filesystem runtime dependency.
  Content Security Policy, no-store, no-referrer and no-sniff headers are
  fixed by the server.

## Controller and Lab parity

The physical controller owns only `Paused | Running | PauseRequested |
Faulted | Completed`. It does not enter `rastok-core`. `PauseRequested` polls
the Driver boundary but starts no new handler; it stops once every already
open outbound Call has a retained completion. Paused Session transports keep
their bounded physical behavior while the VM consumes no Session delivery.
`Paused` and `PauseRequested` also freeze the explicit hosted logical-time
adapter; resume rebases it without altering a retained external result.

The Lab exposes one `ScenarioSession` with an explicit authored-action cursor
and a transaction-boundary API. The old batch runner is implemented through
that same session. The primary simulation `Step in` chooses the next of those two
boundaries without combining them and labels which one comes next; the
specialized next-action control remains available alongside
run-until-assertion, run-to-completion, fresh selection and reset. Reset
rebuilds the VM, journal, mocks, virtual clock and verdict; golden evaluation
remains CLI authority.

The replay recipe records authored actions, VM transactions and productive
Driver polls. Before a branch is admitted, replay
from a clean `ScenarioSession` must reproduce the exact records, VM inspection,
observations, logical time, action cursor, quiescence and failures at the
selected `B`. The original branch remains retained and immutable.

The focused parity proof drives every reference scenario once through the
batch API and once through the interactive API and compares the complete
`ScenarioRun`, including canonical record bytes.

At a quiescent next-`inject` boundary the same session exposes the next authored
input for read-only inspection. The page renders its resolved logical type,
redacted META and redacted DATA, but owns no mutation command. The authored
port, sequence, `meta.ext`, provenance and DATA remain on disk; `meta.sys`
remains absent until the ordinary VM admission mints it.

Fault presentation preserves the same boundary: only a refused VM transaction
is retryable and says that it committed nothing. A Driver/polling failure may
follow a committed transaction; it keeps that history, disables retry and
instructs the user to restart rather than duplicate work.

## Read model and privacy

The snapshot contains validated topology, exact logical time, all retained
causal observations, active logical instances and Node-private cells, open
Calls/Sessions, Lab progress/failures and the public exact `CostReport`.
VM access is through a read-only inspection value; no UI command mutates
state directly.

The owner stores each complete projection synchronously before sending the
replaceable newest-live notification. `/api/timeline` indexes all retained
branches and `/api/snapshot?branch=…&boundary=…` returns an exact frame, so a
fast runner cannot outrun historical capture. Browser history selection is
read-only in both modes. Only simulation exposes `Branch from here`, and the
server accepts it only after exact deterministic replay validation.

The topology read model exposes actual current `Delivery` occupancy and exact
FIFO contents grouped by canonical incoming edge. Each displayed envelope is
redacted before serialization. Boundary outputs and `nothing` drains have no
downstream mailbox, queue badge or synthetic pipe; causal traversal remains visible in the
journal history rather than being mixed with current occupancy. A separate
physical activity slice identifies the exact records advanced by the displayed
boundary: an authored action explicitly names no firing Node, while a transaction
names its owner and trigger. Root and Node `l:start` transactions therefore
remain visible before the first port handler. The snapshot classifies each
causal row and gives it a human summary, so those starts read as instance
openings rather than duplicate entries or ordinary port steps.

Each Graph and executable Node also carries an optional source-faithful debug
entry outside the plan. Pointer or keyboard selection opens the exact authored
declaration — ports, attributes, handlers and guards — beside the graph. The
browser never reparses Rastok or synthesizes source from categorical plan
rows; stripping this physical table removes only the definition panel.

Presentation names the envelope zones `META` and `DATA` rather than using a
UI-only payload label. Committed META includes the exact sys/app/ext zones;
the pre-admission form shows sys as pending, app empty and the authored ext.
Presentation never materializes an encoded value. Every unclassified,
already-materialized DATA root exposes `kind`, `materialized` and its exact
`content`, including plain text; structs, maps, arrays and unions retain exact
numeric, decimal, binary and tagged structure. META and DATA render as compact
DOM trees rather than formatted JSON. The effective annotation table is
consulted before read-model construction: secret, sensitive and personal paths
all use the established non-reveal projection. There is no reveal control and
no post-format masking.

The page constructs content only through DOM/SVG nodes and text content. Its
dependency-free layered DAG is compound: the validated lexical owner tree
places every direct child and nested Graph inside its `App`/Graph frame rather
than inferring scope from paths. Operators remain green and Connectors blue;
compact cards show only name, NodeType and NodeAspects. Hollow input squares
and filled output squares are the exact edge attachment points. Graph/App ports remain
on their owning frame side but slide vertically under the same deterministic
barycentric ordering as connected Nodes. Interval-colored hidden routing lanes
separate coincident approaches before compaction; an identifiable cross-hierarchy
route passes through its nested pin, while an ambiguous flattened seam is never
guessed. The implementation is an original dependency-free asset. The
collision-reduced lane plan remains authoritative while smooth cubic splines
render the complete visible route with horizontal port tangents; arrows stay
compact. A deterministic obstacle scorer places count labels directly on their
curves while clearing every avoidable edge, port label, Node, Graph header and
earlier badge.
Port labels occur once at their pin with a background halo. Current mailbox
occupancy and exact last-transaction highlighting remain. Live owners show an
overlapping-squares icon and instance count; details remain in the Instances
panel rather than as colored keys on the graph. Authored actions, retained
boundaries and causal records
carry distinct `A<n>`, `B<n>` and `R<n>` ordinals. The displayed boundary's
admitted/consumed/emitted routes animate a packet, while a route-less lifecycle
or assertion visibly pulses its owner or boundary banner. Causal history stays
labelled as records rather than boundaries.
Selected definitions are framed in a responsive inspector and remain selected
across snapshot revisions. The page separates topology, causal history,
private state, exchanges, scenario progress and cost. One compact sticky bar
keeps `Rastok UI`, the prominent SIMULATION/RUN mode, execution state and
accessible icon transports visible; CSS follows the system light/dark theme.
Generic operating instructions were removed. Its client table
initially shows the latest 100 records and can reveal every older in-memory row
without truncating the server-side authority. The same Node/Graph selection
filters history, state, exchanges and cost to the exact path or lexical
subtree; clearing it restores the complete read model.

The current front-end refinement keeps those same values but removes the card
dashboard layout. One 32-pixel transport row and one 28-pixel timeline row sit
above a collapsed scenario strip; the pannable and zoomable graph consumes the
remaining left-hand height, separated by a resizable divider from an inspector
switching between Envelope, Mailbox, Definition, Instances and History. Calls,
Sessions and CostReport remain in the runtime
portion of Instances. Graph output pins share one 20-pixel-spaced side
allocation; route paths start and finish at the exact
8-pixel port centers with horizontal tangents. A common fan-out pin shares
only its exact endpoint before the visible routes separate. Unwired Connector
outputs and explicit `-> nothing` drains remain local square ports: neither a
presentation cap nor a synthetic sink invents a spatial destination. A
separate dotted, mailbox-free layer connects validated Graph handler
activations to their possible boundary outputs; `next` is temporal and
`expired` begins at the explicit Loop-manager source. `⧉ n` counts open
instances and `≡ n` counts messages waiting now. Selection
lightens the owning box without recoloring its ports.

The next checked injection is shown read-only from the checked `.rkg` scenario.
The graph is not an IDE and `App.in` does not create a second ingress path. A
retained root-envelope list links back to its boundary frame.
