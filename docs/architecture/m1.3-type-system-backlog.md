# M1.3 backlog — logical payload types and uniform ports

> Implementation record — non-normative. The normative model lives in
> [`types.md`](../spec/types.md),
> [`expressions.md`](../spec/expressions.md), and
> D-2026-08-14-1. This slice replaces the former “typed-error half” of
> M1; it is one semantic landing, not a transitory public model.

## Outcome

M1.3 is complete: Rastok owns one logical type/value domain from
source to journal boundary, every validated port has an effective type,
and Process can complete one job with ordinary typed emissions on
`out`, `err` and `exit`. The former typed-error codes survive as tagged
terminal cases on `exit`; they are generalized, not discarded. The parallel
materialized-value domains are already consolidated in core `value::Value`;
the evaluator-only `expr::EvalValue` can carry a lazy payload witness but is
not a semantic or serializable value. `error_set`, `TypedError` and
failure-only reply routing no longer carry language semantics. Core
`datatype::DataType` has already replaced the former evaluator-owned type for the executable
subset without changing wire ids or hashes.

The user-visible invariant:

```text
type_ref/source
      -> resolution + inference
      -> canonical DataType
      -> ports / state / metadata / expressions / package validator
```

Representation and effects remain orthogonal:

```text
logical type -- Value -- Data::{Materialized | Encoded}
                                      |
                              Connector codec
                                      |
                         meta.ext.content_type
```

## Decisions held throughout the slice

1. No `Dyn` fallback substitutes for an unsolved type. `variant` is an
   explicit dynamic payload type.
2. Source annotations may be absent; effective types in a validated
   plan may not.
3. Connector contracts may be parametric or attribute-dependent. Each
   instantiation resolves to a concrete travelling port table.
4. A codec changes representation. A logical schema change requires an
   explicit Operator/adapter.
5. `in`, `out` and `err` are conventional ports, not a second emission
   mechanism. A Connector conventionally exposes the terminal outcome of
   each admitted invocation on the ordinary typed port `exit`.
6. Every admitted invocation produces `out* + err* + exactly one exit`.
   Call closure is a control fact; the outputs are ordered data facts carried
   by that completion. No emission for the invocation may follow its terminal
   `exit`, and closure is not inferred from a port name.
7. Built-in and registered readers/guests use `IDENT!`; JSON accepts the
   complete JSON value grammar and always returns `variant`.
8. Package v7 is one categorical landing. v6 packages are refused; no
   compatibility shim distorts the new type registry.
9. `graph_version` schema evolution remains distinct: historical schemas
   stay readable, and explicit typed adapters emit new envelopes.
10. Sensitive-data classifications remain a separate future schema
    policy. M1.3 does not pre-allocate syntax or wire tables for them.
11. The same algebra represents the supported JSON Schema, Avro and
    Arrow profiles, including unions. Unsupported or ambiguous
    projections refuse; no adapter degrades them to `bytes` or
    `variant`.
12. `stop` terminates one Node instance; `exit` terminates one Connector
    invocation within it. One Node instance may observe many invocation exits.
    Stopping it cannot erase open call obligations: its later slice must
    refuse admission, then drain or cancel every call under a bounded policy.
13. Framing, publication and aggregation are separate. A framed port may
    emit many envelopes per invocation; on-exit publication or a downstream
    collector may aggregate only under an explicit bound. Correlation is by
    invocation identity, never merely by the owner instance key.

## B0 — Close the normative model

> **Closed 2026-08-14.** The canonical constructors/invariants live in
> `types.md`, the strict external profiles in `schema-projections.md`, the
> frontend in `expressions.md`/`grammar.md`, and the Process completion and
> independent stderr framing in `stdlib.md`. Numeric v7 wire allocation
> remains B8; B0 fixes semantics, not transport ids.

- Land D-2026-08-14-1 and the `types.md` / `expressions.md` authorities.
- Remove current claims that CEL owns scalar computation or logical
  types; retain a named CEL-compatible subset as differential evidence.
- Specify structural versus tagged unions, optionality, alias expansion,
  inference variables and type budgets.
- Publish the JSON Schema / Avro / Arrow projection matrix: widths,
  logical parameters, records, collections, enums, fixed values,
  nullability, union discriminants, and the explicitly unsupported v1
  features.
- Specify the tagged-frontend grammar and supersede the old `TAG_KW`,
  reserved-`json`, `text {}`, `base64 {}` and bare guest forms.
- Freeze the Process port matrix before adapter code: which completion
  cases emit `out*`, `err*`, `exit`, how stdout and stderr are framed, when
  their frames become visible, and whether any partial capture is
  deterministic enough to journal.
- Resolve framing per physical channel. `Process.codec` governs `in/out`;
  `err_codec` governs stderr and defaults to `lines`. `codec = jsonl` plus
  `err_codec = lines` is therefore normal and cannot impose JSON decoding on
  diagnostics. Framing yields unit port values; bounded on-exit publication
  commits them atomically but never silently aggregates them. Freeze the
  effective port types with this attribute surface.
- Require every call-bearing Connector contract to declare both successful
  and unsuccessful terminal cases in its `exit` union; a response on `out`
  never silently doubles as call closure.
- State the scope boundary explicitly: M1.3 implements per-invocation exit;
  the subsequent instance/lifetime slice implements bounded stop/drain/cancel while
  preserving every admitted invocation's terminal obligation.

Exit: no normative document requires `error_set` or calls a Process
lifecycle outcome stderr.

## B1 — One core type and value domain

> **Closed 2026-08-14.** Ownership and the complete canonical `DataType` and
> materialized `Value` algebras have landed for the strict JSON Schema, Avro
> and Arrow profiles. Widths, fixed sizes, temporal parameters and timezone
> remain in the resolved type rather than being copied into each envelope;
> values carry the canonical data plus enum/union discriminants. The shared
> conformance judge now covers exact binary16/32 promotion, all temporal and
> interval profiles (including Avro's unsigned duration shape), UUID, fixed
> collections and text/non-text maps with canonical keys. Validation, equality
> and canonicalization share that value domain; the evaluator-only payload
> witness still cannot cross a materialized boundary. Private v6 refused every
> newly represented family; B8 now publishes the sole v7 registry.

- Introduce the no_std-ready canonical `DataType` tree in the core.
- Move the materialized `Value` authority beside it; cover scalars,
  structs, maps, arrays, enums, structural unions, tagged unions and
  variants.
- Extend the landed single conformance, validation, equality and
  canonicalization rules to every new type/value family.
- Keep lazy payload carriage internal to evaluation; it must never be a
  serializable value case.
- Preserve the existing `Data::{Encoded, Materialized}` representation
  split and the causal irrelevance of its lazy cache.
- Provide schema-neutral projection inputs/outputs in the core; keep
  Avro, Arrow and JSON Schema library types in std/boundary adapters.

Exit: no semantic conversion between two independently-owned value
domains remains.

## B2 — Resolve types rather than defaulting them

> **Closed 2026-08-14; v7 transport closed by B8 on 2026-08-15.**
> `ValidatedExecutionPlan` now owns a total `ResolvedPortTable` beside the
> raw package tables. Compiler-only variables collect source annotations,
> codec-selected Process pins, edges, handler activations, emissions, field
> reads and state requirements; each resulting row carries one canonical
> `DataType` and `Declared` or `Inferred` origin. An unsolved variable and
> incompatible constraints refuse as typed `E-PORT-TYPE` diagnostics;
> explicit `variant` is directional (precise → variant is allowed, variant →
> precise requires future narrowing). Ingress, operator emissions, partner
> replies and raw-plan validation all consume the resolved table. V7
> transports that already-enforced table and deterministically re-derives it
> on decode. The temporary Process rules (`lines`, `jsonl`, legacy
> `err`, legacy JSONL aggregation) moved into `PortContract` at B5/B7. An
> intermediate closure made the VM's synthesized Operator runtime-fault row
> explicit in that table. Final M1.3 review rejected the premise instead:
> Operators have only program-declared/inferred ports, an explicit `err: E`
> is ordinary domain data, and an engine fault aborts the transaction and
> reaches supervision. The pre-commit gate still asserts that every real
> emission and fan-out endpoint resolves.

- Resolve named aliases structurally and reject recursion/budget excess.
- Add compiler-only type variables and constraints.
- Separate `Declared` from `Inferred` origin while requiring an
  effective `DataType` in the validated plan.
- Make port, state and metadata subset checks consume the same type
  authority.
- Prove that `variant`, an unresolved variable and an error-recovery hole
  never collapse.

Exit: every boundary and node port in a `ValidatedExecutionPlan` has an
effective type or compilation fails.

## B3 — Rebase the expression engine

> **Closed in the semantic core 2026-08-14; v7 transport landed
> 2026-08-15.** The module/API is `expr`, its signatures and trees consume
> `DataType`/`Value`, and `EvalValue` remains evaluator-only. `is`/`as`
> implement typed, flow-sensitive narrowing for precise, structural-union
> and tagged-union targets, including explicit discriminators and distinct
> no-match/ambiguity/configuration failures. The compatible operator corpus
> is differentially executed against exact-pinned `cel-interpreter 0.10.0`;
> the divergence ledger and dependency exit strategy live in
> `expressions.md`. Private v6 deliberately had no spelling for the new AST;
> B8 assigns it once in v7.
> The unchecked `variant` access door assigned to B9 is now closed. Exact
> decimal values already belong to the Rastok value algebra; B8 changed the historical
> private-v6 tree type from `variant` to canonical `number` in the registry move.
> The 2026-08-15 adversarial closure added exact rescaling into fixed decimals
> and made structural-union indexes type-relative: implicit union-to-union
> flow requires identical resolved types, while explicit narrowing reselects
> the target index.

- Rename the conceptual/code boundary from `cel` to `expr`; migrate
  `CelExpr`, signatures, trees and bindings without rewriting the proven
  parser/evaluator algorithms unnecessarily.
- Preserve the landed `DataType`/`Value` ownership; keep `EvalValue` strictly
  evaluator-only and prevent its payload witness from crossing a materialized
  boundary.
- Preserve the differential CEL harness for the explicitly compatible
  operator subset and add a versioned divergence table.
- Make exact decimal an ordinary Rastok type/value and constructor.
- Implement the minimum `is`/`as` rules required for `variant` and
  tagged-union use, including one typed failure path.
- Make a JSON `variant -> union` check deterministic: discriminator when
  declared, otherwise exactly one conforming branch; zero and ambiguous
  matches are distinct refusals.

Exit: the expression module is a consumer of the payload model, never its
type authority.

## B4 — Tagged frontends on one syntax

**Landed 2026-08-15.** The parser selects `IDENT!` from byte-adjacent
syntax alone, then asks the compiler Registry for the frontend contract.
JSON, text, base64, deferred guests and reserved data formats share that
door; `asset`, `duration` and `decimal` remain expression calls. Scalar
JSON is executable again, frontend names are bindable, `json!=x` stays an
expression, and registered framing is covered by a custom-frontend test.
The effective HIR and package identity of migrated valid programs are
unchanged; B4 adds no plan-format form.

- Add the host `!` token and left-factor `IDENT !` before expression
  continuation, with no rewind or keyword registry in the production
  choice.
- Require byte adjacency between the frontend name and `!`. A frontend owns
  one complete host `value`, not an atom inside an intrinsic expression;
  `val x = json! 2` is valid and `1 + json! 2` refuses. Pin maximal munch so
  `json!=x` remains the expression `json != x`.
- Migrate `json`, `text`, `base64`, jq/SQL and reserved format readers to
  `IDENT!`; leave `asset`, `duration`, `decimal` as expression calls.
- Restore scalar JSON through the house reader; pin result type
  `variant`, exact-number behavior, recovery boundaries and trailing
  input diagnostics.
- Route built-in and registered names through one frontend contract.
- Keep framing semantic: JSON self-frames; a guest frontend owns its
  registered framer. Do not recreate a universal host scanner.

Exit: frontend names are ordinary bindable identifiers, and every
special region begins with the same unambiguous form.

## B5 — Uniform port contracts

> **Landed 2026-08-15.** One validated `PortContract` table now resolves
> fixed, same-as, common-choice and profile-selector rules into complete typed
> Connector rows. No real contract paid for a constrained generic rule, so no
> placeholder inference abstraction was added. Direction and unwired policy
> travel with each row; the VM consults `RootSink`, never a port spelling.
> `Process` now declares `in/out/err/exit`, accepts `codec = bytes`, injects
> `err_codec = lines`, and the Registry-free plan gate verifies all four rows.
> At B5, the private-v6 carriers stayed honest about the pre-B7 seam (`jsonl` output was
> `array<variant>` and `err/exit` are `variant`); bytes adapter framing is a
> named B7 bind refusal, not a fallback. The old-fact migration table fixed the
> target `ProcessExit` cases beside that seam. `error_set` is gone, its package
> key is retired, and the deliberate hash/package moves are recorded in
> D-2026-08-14-1. B7, not this gate, changes framing multiplicity and completion.

- Replace the three flat contract lists plus `error_set` with resolved
  `PortContract` rules under one direction/type model.
- Support fixed, same-as, attribute/profile-selected and constrained
  inferred port types; implement only rules paid for by real contracts.
- Materialize every conventional port promised by a resolved contract,
  including a Connector's `exit`, instead of teaching runtime sites their
  names.
- Desugar conventional routing/sink policy into plan data; no VM string
  comparisons confer a second port category.
- Resolve Process codec-dependent pins from this one contract authority.
  The real sheet must introduce `codec = bytes` and
  `err_codec ∈ { lines, bytes }`, defaulting to `lines`; neither may remain
  merely normative prose.
- Treat injection of the new `err_codec` default and removal of `error_set`
  as deliberate identity moves. Enumerate the affected Process packages,
  hashes and goldens in the B5 change rather than discovering the move during
  B7.

Exit: the package validator proves the complete port table without a
compiler Registry.

## B6 — Tagged sums and ordinary emissions

> **Landed in the checker/HIR 2026-08-15; v7 wire publication landed in B8.**
> `Case { ... }` is one predictive host-value production. The checker
> resolves its exact tagged union, closes and sorts the payload fields, and
> records a typed `expr::Expr::Tagged`; an obsolete configuration initializer
> with no genuine case retains its migration. Structural-union construction
> inserts one `As` node at the typed destination, including nested optional
> case fields. Different union types still require source-written `as`.
> `err` now follows the same syntax/HIR `Statement::Emit` path as every other
> output; `ErrEmit` is gone. V6 rejects constructor and wrapping expression
> nodes categorically; B8 now assigns their v7 tags and package bytes. The
> final review also removed the unrelated synthetic `RuntimeFault` emission:
> no output name is an engine-fault trap, and an Operator need not have
> `err` at all.

- Give tagged unions a canonical, name-stable case representation and
  constructor `Case { ... }` in general value position.
- Supersede the dead struct-bodied *initializer* rule only for genuine
  value constructors; retain migration diagnostics for obsolete config
  forms.
- Remove `ErrEmit`/`err_value`; lower every port assignment to the same
  `Step::Emit` path.
- Insert contextual union wrapping once at check/lowering for a compatible
  assignment, emission or case field (`out = 5` into `int32 | text`, or
  `signal = null` into `int32?`). Zero/ambiguous matches refuse
  `E-PORT-TYPE`; authors do not write `as` for this ordinary construction.
- Require explicit `as` for conversion between different structural-union
  types so the target branch is reselected. Validate construction/narrowing
  at check and package validation; the final runtime gate verifies but never
  wraps, repairs or re-indexes a value.

Exit: any compatible port may carry a tagged union; nothing in the
mechanism is error-specific.

## B7 — Multi-output boundary completion, typed exits and Process

> **Implementation checkpoint (closed 2026-08-15).** `Completion` now owns
> ordered `EnvelopeDraft` drafts and structurally requires one final `exit`;
> `CompletionCheck` validates every Process draft, including the exact
> materialized `ProcessExit`, before journal closure. The VM alone mints the
> envelopes and commits all drafts in one transaction. The real adapter and
> Lab mocks share this seam. `lines`, `jsonl` and `bytes` produce unit stdout
> values, `err_codec` frames stderr independently, every observed process
> status is `Exited`, and scheduler/adapter terminal facts use the other
> declared cases. The old `CallOutcome`/`TypedError` seam is deleted. B8 removed
> the former raw-v6 `Process.exit: variant` bridge.

- Open the implementation with the old-fact → `ProcessExit` migration table
  fixed in D-2026-08-14-1. In particular, `StderrLine` becomes ordinary
  `err` data, `DecodeError` becomes `DecodeFailed`, and `ExecFailed` becomes
  `Exited` plus independently framed stderr; mapping by nearest name is not
  allowed.
- Replace success/failure-only boundary replies with one completion fact
  carrying ordered `EnvelopeDraft { port, data, ext }` drafts.
- Keep envelope construction, identities and journal `Emission`s inside
  the VM; a Partner never manufactures journal records.
- Close the call from the completion control fact, not from a selected
  output port; require exactly one typed `exit` draft and reject any output
  after it for the same invocation.
- Define `Process.exit` as the `ProcessExit` tagged union. `Process.err` is
  exact stderr data under its resolved framing; `Process.out` is stdout
  interpreted by the selected reply codec.
- Implement `codec = bytes` for stdin/stdout and independent
  `err_codec = lines | bytes` framing from the B5 contract; no data codec is
  reused implicitly for stderr.
- Emit `Exited { exit_code, signal }` for every observed child exit,
  including non-zero codes; the graph decides policy.
- Map spawn, timeout, output budget/capacity, capture and decode facts to
  named exit cases without folding stderr into them. This is the original
  typed-error deliverable, expressed in the general port/type model.
- Carry invocation identity on every output and prove two concurrent calls
  in one Node instance cannot mix their frames or terminal cases.
- Keep framing separate from publication: prove the bounded on-exit job
  transaction with zero or more ordered `out`/`err` emissions, and leave a
  streaming profile behind the same no-output-after-exit barrier.
- Extend Lab mocks and expectations to produce/verify the same atomic
  multi-port completion.

Exit: a real job and its mock can both produce `out* + err* + exactly one
exit` in one bounded transaction, wiring only `exit` is a normal graph, and
every former typed error code is testable as a `ProcessExit` case.

## B8 — Package v7 and identity move

> **Landed 2026-08-15.** One extend-only registry now transports every
> canonical `DataType`, every allocated materialized-value family, the full
> expression alphabet and the mandatory total `ResolvedPortTable`. Decode
> reconstructs and compares the effective table without a compiler Registry;
> malformed/overlapping unions, invalid parameters, unresolved ports and
> budget excess refuse before execution. V6 is refused categorically. The
> deliberate hash/package moves and embedded re-measurement are recorded in

- Specify the canonical resolved-type registry before encoding it:
  scalar parameters, struct-field ordering, enum/case names, union
  discriminants, recursion and byte budgets.
- Pin external-schema mappings independently of library iteration order:
  Avro branch indexes and Arrow type codes map explicitly to canonical
  union discriminants; Arrow dense/sparse and Avro container layout do
  not enter the logical type identity.
- Serialize complete effective port/schema types and expression trees
  against that registry; reject unresolved variables and invalid unions.
- Adopt the already published, extend-only value tags for every B1 family

  the new type/expression registry. Backward package compatibility is not a

- Bump once to v7, reject v6 categorically, re-bless packages/hashes and
  re-measure the embedded spike with the semantic reason recorded.
- Keep plan-package format migration separate from `graph_version`
  schema adapters.

Exit: decode + validation answer from package bytes alone, and sabotage
tests cover every new table invariant.

## Scope protection

M1.3 deliberately does **not** implement journal migration, recursive
types, Process service mode, the Node-instance runtime or bounded stop/drain/cancel,
arbitrary guest framers, sensitivity-label propagation or a runtime Registry.
It does fix the invocation/instance scope contract that those later slices
must implement. If schedule pressure appears, later M1 breadth is reduced;
this foundation is not replaced by a temporary public error/type model.
