# M1.8 — data policy, secrets, observations and cost

> Ordered implementation backlog, prepared 2026-08-30 under
> [D-2026-08-30-1](../spec/decisions.md). Recognizing an annotation does not
> make its policy executable: every gate remains fail-closed until its
> transport, Registry-free validation and boundary evidence land together.

**Current checkpoint:** A0–A3.1 are closed on categorical package v15 and A4 is
open. The closed annotation family crosses source, checked HIR, lowering,
package encode/decode and Registry-free validation as a sparse canonical
side-table beside each owning schema. A3 derives effective policy through
canonical operations, rejects incompatible accounting alternatives and
redacts before presentation. A3.1 adds the orthogonal GDPR-facing personal-data
class, including subject-identifier and Articles 9/10 flags. Clear secret and
personal payloads remain fail-closed pending A4's attested deployment
boundary. Existing causal traces and unannotated semantic
hashes remain byte-identical.

## Exit statement

M1.8 is complete when all of the following are executable together:

- `@sensitive`, `@secret`, `@personal`, `@measure` and `@cost` form one closed data-
  annotation model beside `DataType`, without changing type assignability;
- annotations survive source, checked HIR, categorical package, independent
  decode/validation and execution at their exact canonical schema paths;
- sensitive values are redacted before formatting, and secret material can
  reach only a declared secret-compatible Driver boundary without entering a
  package, journal, diagnostic, log or trace in clear;
- the journal remains the sole accounting authority and yields exact,
  replayable per-flow measures and costs even when every exporter is disabled
  or dropping data;
- OpenTelemetry semantic conventions name every measure for which they define
  an exact match; the `rastok.*` namespace is used only for Rastok-specific
  concepts;
- monetary observations use exact decimal quantities plus one currency,
  never float, an implicit exchange rate, or an unknown value coerced to zero;
- the observation projection is bounded and never blocks execution; dropping
  a projection cannot change the journal or `CostReport`;
- programs without annotations pay no schema walk on the hot path and retain
  their existing semantic hashes and causal traces.

OpenTelemetry export is a qualification gate, not the foundation's authority.
If the M1 calendar requires the cut, A6 moves after M1 and the exit statement
is otherwise unchanged.

## Architecture

```text
source type + annotations
          │
          ▼
 AnnotatedSchema
   ├── DataType                         (assignability authority)
   └── SchemaPath -> AnnotationSet      (policy/accounting authority)
          │
          ├── checker propagation and boundary policy
          └── categorical package + Registry-free verification

runtime transaction / Driver observation
          │
          ▼
 journal causal record + RecordObservation
          │
          ├── deterministic fold ───────────────▶ CostReport
          │
          └── bounded never-block projection
                    ├── structured JSON logs
                    └── hosted OpenTelemetry exporter
```

There is no metrics ledger beside the journal. Export queues are disposable;
the facts from which reports are rebuilt are not.

## Invariants frozen before code

1. A data annotation never creates a logical type and never changes ordinary
   `DataType` conformance or assignability.
2. A source annotation that changes policy or accounting is semantic identity.
   Formatting and annotation order are not.
3. The resolved table is a canonical side-table. No `Annotated<DataType>`
   wrapper recursively pollutes the type algebra.
4. Annotation names, arguments and legal targets are closed. Arguments are
   plan constants; expressions, open maps and runtime bindings refuse.
5. Unknown, duplicate, mistargeted or forged annotations refuse by exact path.
6. `@secret` is stronger than `@sensitive`. Secret bytes never enter a normal
   `Value`; a `SecretRef` crosses only the declared late-resolution boundary.
7. A raw incoming field marked `@secret` refuses until a later field-level
   externalization protocol can replace it with a reference before journaling.
8. `@personal` is orthogonal to confidentiality; it redacts by default and
   requires an attested privacy profile before execution. A future durable
   journal must prove erasure or externalization before retaining it in clear.
9. `RecordObservation` is typed. A universal string map is not an authority.
10. Observation exporters are never an input to execution, replay, accounting
   or budget decisions.
11. A measure that is absent or unpriced remains absent or `unpriced`; it is
   never materialized as zero.
12. OpenTelemetry names take precedence when their definitions match exactly.
   Rastok never publishes an alias for an existing standard name.
13. High-cardinality correlation belongs to spans, logs and `CostReport`, not
   to metric labels by default.
14. The core parses no human configuration format and contains no exporter or
   hosted secret-store dependency.

## Closed source vocabulary

```ebnf
annotated_type       ::= type_ref data_annotation*
data_annotation      ::= "@" IDENT annotation_arguments?
annotation_arguments ::= "(" named_annotation_argument
                         ("," named_annotation_argument)* ")"
named_annotation_argument ::= IDENT "=" annotation_constant
```

The five M1.8 annotation identities are extend-only:

| Source form | Canonical identity | M1 meaning |
|---|---|---|
| `@sensitive(level = internal\|confidential\|restricted)` | `rastok/sensitive@1` | redaction and controlled propagation |
| `@secret` | `rastok/secret@1` | secret handling policy; never the secret origin |
| `@personal(special = bool?, criminal = bool?, identifier = bool?)` | `rastok/personal@1` | GDPR personal-data class, legal regimes and exact subject-id role |
| `@measure(id = ...)` | `rastok/measure@1` | bind one typed field to a registered semantic quantity |
| `@cost(currency = ..., basis = ...)` | `rastok/cost@1` | bind an exact monetary field to its currency and evidence basis |

`secret("path")` is the origin of a `SecretRef`; `@secret` classifies how a
value must be handled. The two are related but not interchangeable.

## Initial measure registry

The registry pins whether an entry is an OpenTelemetry attribute or instrument,
its carrier, canonical unit, aggregation and subset relations. The source
annotation names the semantic field quantity; it does not repeat a unit.

### OpenTelemetry-first entries

- `gen_ai.usage.input_tokens`
- `gen_ai.usage.output_tokens`
- `gen_ai.usage.cache_read.input_tokens`
- `gen_ai.usage.cache_creation.input_tokens`
- `gen_ai.usage.reasoning.output_tokens`
- `gen_ai.client.token.usage`
- `gen_ai.client.operation.duration`
- `gen_ai.client.operation.time_to_first_chunk`
- `gen_ai.client.operation.time_per_output_chunk`
- `http.client.request.duration`, `http.client.request.body.size` and
  `http.client.response.body.size`
- `http.server.request.duration`, `http.server.request.body.size` and
  `http.server.response.body.size`

Input-token totals include their cache sub-counts; output-token totals include
reasoning tokens. The registry records these subset relations so a report or
price profile cannot sum them blindly.

### Rastok-specific entries

- per-flow admitted/emitted envelope count, payload bytes and duration;
- per-Connector calls, terminals, timeouts, retries, open calls and duration;
- instance mailbox depth/count/evictions and per-edge lag;
- journal size/low-water mark and dropped observation projections.

Their final exported spellings use `rastok.*`. Gauges such as mailbox depth
are operational observations and never enter `CostReport`; exact calls,
bytes, durations and tokens may.

## Ordered gates

### A0 — Close the decision and negative space

- Publish D-2026-08-30-1, this backlog and the non-normative Budget draft.
- Reconcile types, grammar, identity, execution, delivery, simulation,
  stdlib, Whitepaper and roadmap terminology.
- Pin the exact OpenTelemetry semantic-convention snapshots used by the
  registry and record the dependency state before any hosted exporter lands.
- Freeze the package-v15 move, semantic extension and non-causal observation
  keys before re-blessing any artifact.
- Name every later gate: Budget, quota reservation, FX, billing/FOCUS,
  OpenCost allocation, raw secret externalization, hot secret rotation,
  arbitrary user measures and dimensions.

**Exit:** one coherent normative target and no code path that treats recognized
annotation syntax as executable policy.

### A1 — Parse and check one closed annotation model

- Tokenize `@` as host syntax and attach annotations to type positions.
- Parse named constant arguments and retain exact spans.
- Introduce `SchemaPath`, `AnnotationSet`, the four typed annotation specs and
  a registry-owned `MeasureId` in the no-std core.
- Expand alias annotations onto resolved paths and reject unknown names,
  duplicates, bad arguments and illegal targets with one diagnostic family.
- Keep execution fail-closed until A2 transports the resolved table.

**Exit:** focused parser/checker tests cover field, port, collection-element
and union-case targets plus every refusal class; unannotated syntax trees and
semantic hashes are unchanged.

**Opening checkpoint (2026-08-30):** `@` is one host token; the source tree
retains named constant arguments on exact type positions and tagged-union
cases; `SchemaPath`, `AnnotationSet`, `AnnotatedSchema`, the four typed
annotations, canonical measure ids and exact currency spellings live in the
no-std core. Ten structural/canonical core tests plus lexer/parser/checker
probes are green. Resolution, target legality, alias expansion and v15 remain
open, so any source annotation produces `E-CHECK-DEFERRED` rather than losing
policy metadata.

**Closure checkpoint (2026-08-30):** the checker now resolves all four typed
annotation contracts, rejects unknown/duplicate/dynamic/mistargeted forms
through `E-DATA-ANNOTATION { annotation, path, detail }`, distinguishes field
measures from runtime instruments, verifies the pinned ISO 4217 registry and
expands aliases through fields, collections and both union forms. Named types,
ports, typed values, state cells and local typed bindings retain their sparse
tables in HIR. At the A1 checkpoint a valid annotated unit stopped at one
categorical-v15 deferral and lowering carried an independent fail-closed belt;
A2 has since superseded those temporary gates. Twelve core annotation tests
plus lexer/parser/checker target and refusal matrices were green. Unannotated
semantic witnesses and traces remained unchanged.

Decode re-derives path resolution, target legality, measure membership and
carrier, currency authority, local declared/resolved equality and canonical order

### A3 — Enforce propagation and redaction policy

- Preserve annotations through exact copy/projection/rename.
- Propagate the maximum sensitivity and secret taint through derived values.
- Drop measure/cost meaning on calculation unless a registered rule proves
  the output meaning.
- Treat opaque guest output conservatively for secret/sensitive policy.
- Re-derive every result at check and validation; the VM consumes verdicts.
- Add a zero-walk fast path for schemas whose annotation table is empty.

**Exit:** policy cannot be lost by a transform, invented by a calculation or
recovered at runtime from strings.

**Closure checkpoint (2026-08-30):** one Registry-free fixed point derives
policy for boundary, Node and nested-Graph ports, lexical owner values, state,
local bindings, guards, field writes and Loop recurrence. Exact operations
preserve policy. Calculations and control dependencies keep only the maximum
security taint; alternative producers must agree exactly on measure and cost
meaning. Raw declarations remain unchanged while the categorical resolved
table carries the effective verdict and decode derives it again. A plan with
no annotation takes a zero-operation-walk validation path. Sensitive values
execute; clear secret-classified plans retain the A4 fail-closed belt. CLI,
Lab, evaluator and codec faults never format classified payload values.
Opaque guests remain refused rather than bypassing the conservative-taint
seam. A3 adds no format, semantic-extension or causal-record identity move;
unannotated packages, witnesses and traces remain exact.

Closure gates: 943 all-feature tests, fmt/clippy/doc without warnings, all

### A3.1 — Add the GDPR-facing personal-data class

- Append `@personal` as wire tag 5 without moving any existing annotation,
  package or semantic identity.
- Keep `special`, `criminal` and `identifier` as independent optional boolean
  flags; plain `@personal` means ordinary personal data.
- Preserve exact identifier meaning only through copy/projection; retain legal
  taint but clear the identifier claim after unregistered calculations.
- Redact personal data by default and refuse execution pending A4's attested
  privacy profile.
- Keep purpose, legal basis, recipients, transfers and retention in deployment
  policy rather than reusable source types. Name the durable-journal
  erasure/externalization gate explicitly.

**Exit:** parser/checker, core propagation, v15 round-trip, semantic framing,
redaction and pre-mutation fail-closed tests agree on one orthogonal class;
every earlier package, semantic witness and causal trace remains unchanged.

**Closure checkpoint (2026-08-30):** `PersonalDataClass` and
`rastok/personal@1` cross the complete A1–A3 mechanism with append-only wire
tag 5. The checker accepts only the three boolean flags and exact paths;
Registry-free decode validates the closed flag mask. Copy preserves subject-id
meaning, calculation clears it while retaining Article 9/10 taint, and
presentation redacts without manufacturing a sensitivity level. VM boot
refuses the first personal-data site before mutation until A4 can attest a
privacy profile. This additive registry extension leaves categorical v15 and
all pre-existing bytes unchanged.

Closure gates: 949 all-feature tests, fmt/clippy/doc without warnings, all

### A4 — Bind deployment values and late-resolve secrets

- Put typed `DeploymentProfile`, `BootBindings`, `SecretRef`, attestations and
  the `SecretProvider` seam in core; add a versioned `PrivacyProfileRef` for
  personal-data plans; keep JSON/CLI/environment parsing hosted.
- Lift `env()`/`secret()` only at declared boot-compatible Connector settings.
- Ship a scripted Lab provider and the smallest hosted provider justified by
  the deployment profile; do not put secret contents on the CLI.
- Journal provider/path/version attestations in the run header before use.
- Attest processing activity, purposes, legal basis, retention, recipients and
  transfer safeguards before admitting personal data; validate coverage, not
  the controller's legal judgement.
- Reject missing versions, unavailable providers, non-secret-compatible sinks
  and raw incoming `@secret` fields before any effect. Reject personal data
  without a privacy profile or on a journal lacking the required retention /
  erasure capability.

**Exit:** a real authenticated Connector call and its scripted twin use the
same plan while no secret value appears in any inspected artifact; one
personal-data flow boots only with an attested run-scoped privacy profile.

### A6 — Qualify hosted OpenTelemetry export (calendar-optional)

### A7 — Fold exact measures and cost reports

- Record exact additive measure samples and provider-reported monetary facts
  as typed observations outside the causal seal.
- Define canonical `Money` as the resolved struct alias
  `{ amount: decimal(38,18), currency: text }`, not a `DataType` family.
- Load an optional deployment `CostProfile` whose id and digest accompany each

- Keep provider-reported and pricebook-calculated bases separate.
- Fold by origin, instance, Node, Connector, provider/model and currency;
  report unknown rules as `unpriced` and never form a cross-currency total.
- Expose one `CostReport` API for the later `--watch`, FOCUS and OpenCost

**Exit:** replay reconstructs the same report with exporters disabled, handles

## Named limits

- No `Budget` aspect, quota, reservation or pre-effect refusal in M1.8.
- No FX, billing authority, FOCUS-conformance or OpenCost allocation claim.
- No automatic model selection, sampled calibration or price prediction.
- No arbitrary user-defined measure/dimension registry in the first format.
- No raw secret-bearing envelope, field-level secret externalization, hot
  rotation or claim of encrypted durable-journal storage.
- No claim that annotations alone prove legal compliance; no durable clear
  personal-data journal before an erasure/externalization protocol lands.
- No hosted parser, exporter, cloud/Vault client or price database in
  `rastok-core`.
- `--watch` consumes this slice but remains the following M1 item.
