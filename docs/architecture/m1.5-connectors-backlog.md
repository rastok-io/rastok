# M1.5 — Connector contracts, Drivers, and `File`

> **Status:** active implementation backlog. D-2026-08-22-1 is the semantic
> authority. A gate is closed only by code, focused negative proofs and the
> relevant repository gates; prose alone does not close it.

## Question and exit statement

M1.5 answers one question:

> Can one validated plan execute several real connector families without VM
> special cases, while preserving typed ports, journal-before-effect,
> deterministic replay, bounded Closing and production/mock parity?

The slice exits when one source program can bind and execute both
`rastok/process@1` and `rastok/file@1`; every required role is proven before
the journal opens; the Lab substitutes Drivers through the same binding; a
replay never re-reads the filesystem; and adding a third statically linked
Connector requires contract, Driver and conformance code but no VM branch.

## Architecture under test

```text
RKG Connector declaration
          |
          v
  ContractCatalog -------- compile/check/lower --------> categorical plan
  (semantic sheets)                                  contract id + facts
                                                            |
                                                            v
  DriverRegistry -------- available factories ------> Runtime binder
  (physical build)                                      /          \
                                                       v            v
                                      InboundConnectorDriver  OutboundConnectorDriver
                                               \             /
                                                \ shared state
                                                 v
                                       VM <-> journal boundary
```

The plan never names a crate, library path, Cargo feature, Host or Worker.
Static registration is the M1.5 implementation. Native and out-of-process
plugin loaders are later producers of DriverRegistry entries, not alternate
execution models.

## Ordered gates

### C0 — Freeze the seam and vocabulary

- Record D-2026-08-22-1 and this backlog.
- Rename the runtime interfaces to `InboundConnectorDriver` and
  `OutboundConnectorDriver` without changing behavior.
- Turn the monolithic `connectors.rs` into a connector-owned module tree; keep
  `Process` behavior and public paths compatible for this checkpoint.
- Update current architecture documents. No hash, package or trace may move.

**Exit:** the workspace and conformance battery are green; grep finds no
active Rust `Ingress`/`Partner` interface; all stored semantic artifacts are
byte-identical.

### C1 — Stable contract identity and separate registries

- Introduce a validated `ConnectorId` with canonical
  `<namespace>/<name>@<major>` spelling and no lossy aliases.
- Key compiler `ContractCatalog` and runtime `DriverRegistry` by that type.
- Transport the identifier categorically; validate it Registry-free after
  decode. Allocate one plan-format bump and publish the complete identity
  move before changing goldens.
- Reject missing, role-incomplete and duplicate Driver registrations with
  typed binding failures.

**Exit:** Process compiles under `rastok/process@1`; forged identifiers and
ambiguous registrations refuse; the connector-free gauge remains the scope
witness.

### C2 — One binder for every role and connector family

- Replace `Process::try_new(plan)` as the application binder with one
  `RuntimeBindings::try_new(plan, registry)` pass.
- Bind every callable Outbound role and every runnable Inbound role before VM
  construction. A source-only connector is not mistaken for an unserved
  caller.
- Let one factory expose both roles over shared state where its contract
  requires both.
- Route calls and cancellations through bindings without matching concrete
  connector names in the VM.

**Exit:** a plan containing two fake connector families binds and routes both;
missing/extra/wrong-role implementations fail before any journal record or
effect.

### C3 — The `File` sheet and invocation settings

- Publish `rastok/file@1` with outbound `read` and `replace` profiles, exact
  typed ports and portable terminal union cases.
- Lift invocation-phase dynamic Connector settings for the file path through
  source → checker → plan → binding/intent. The Driver receives only values
  already resolved and validated for that call.
- Refuse directory operations, implicit parent creation and `watch` by name.
- Decide and document replacement atomicity, metadata preservation,
  maximum-read budget and path/platform normalization before implementation.

**Exit:** the contract sheet validates, path expressions type-check at the
invocation phase, and every unsupported spelling has one focused negative
test.

### C4 — Real `File` Driver

- Implement one-file reads and bounded atomic replacements behind
  `OutboundConnectorDriver`.
- Open the outbound record before filesystem observation/effect; completions
  re-enter as ordinary typed port outputs with exactly one terminal `exit`.
- Make late completion, cancellation and Closing obey the generic boundary
  protocol. Replay consumes journaled outcomes and never touches the file.
- Contain OS-specific details at the Driver edge; do not expose raw errno or
  unstable platform strings as causal payload.

**Exit:** focused real-filesystem integration tests cover success, absence,
  permission/shape failures where portable, budget, replace, cancel and
  replay-with-file-changed.

### C5 — Conformance, Lab, and build composition

- Run Process and File through the same role-aware conformance harness.
- Register real and mock factories explicitly; prove minimal Process-only,
  File-only and combined static DriverRegistry compositions.
- Prove mocks cannot bypass contract identity, role binding, typed completion
  or journal ownership.
- Measure File-specific implementation work separately from the one-time
  binder/registry tax before repeating the “half-day connector” claim.

**Exit:** one scenario uses both connector families, the combined real plan
and Lab plan share semantic identity, and no VM/file-specific dispatch exists.

### C6 — Closure and future-plugin audit

- Sweep `README.md`, `ROADMAP.md`, specs, diagrams and examples for the old
  seam vocabulary and single-Driver assumptions.
- Verify that a manifest can describe contract identity and roles without
  loading implementation code; do not ship a plugin loader or freeze an ABI.
- Run full workspace gates, all no-std target checks and the QEMU spike; list
  every package/hash/trace move and its reason.

**Exit:** a connector contributor has one documented path — contract,
factory/Driver, conformance profile — regardless of whether a future build
links it statically or discovers it through a plugin host.

## Named limits after M1.5

- `File.watch` and directory traversal are not implemented.
- Native `.so`/`.dll` ABI, plugin trust/signing, process isolation and hot
  reload are not frozen.
- Distributed Driver placement and leases remain physical Host/Worker work;
  connector IDs and causal records contain no placement facts.
- Graph lifecycle handler source syntax remains attached to the later Loop
  slice, not to connector binding.
