# M1.5 exit report — Connector contracts, Drivers, and `File`

> Closed 2026-08-23; adversarial closure pass sealed 2026-08-24. Normative authority:
> [D-2026-08-22-1](../spec/decisions.md). Ordered implementation record:
> [`m1.5-connectors-backlog.md`](m1.5-connectors-backlog.md).

## Verdict

M1.5 answers its question positively: one validated plan can bind and execute
several real Connector families without a concrete-family branch in the VM.
Every active role is proven before the VM or journal exists; real and Lab
Drivers use the same exact contract identity, family request protocol, result
types and runtime bookkeeping; replay never repeats a closed File observation
or effect.

Process and File are the two real outbound families. A combined source binds
both through one `DriverRegistry`; Process-only and File-only registries bind
their reduced plans and refuse a mixed plan that requires the omitted family.

## The architecture that exited

```text
source symbol
    │
    ▼
ContractCatalog ── check/lower ──▶ validated plan
semantic sheets                  stable Connector id + required roles
                                          │
                                          ▼
DriverRegistry ── exact pre-VM bind ──▶ RuntimeBindings
physical factories                        │
                                          ▼
                                  one VM + one journal
```

- **Connector** is the RKG Node.
- **Contract** is compiler-visible semantic data.
- **Driver** is one physical implementation.
- **Binding** is the verified plan-Node-to-Driver association.

There are exactly two roles relative to the Rastok boundary. An
`InboundConnectorDriver` proposes external arrivals; an
`OutboundConnectorDriver` serves already-journaled calls. A both-role contract
binds one shared object exposing both views.

The plan carries the canonical `<namespace>/<name>@<major>` contract id and
closed role value. It never carries a crate, Cargo feature, library path,
Driver build version, Host or Worker. Registration order is not selection:
unknown ids, missing roles, duplicate factories and factories whose bound
views contradict their advertised roles are typed pre-execution failures.

## Gate evidence

### C0 — one vocabulary and module boundary

The active Rust `Ingress`/`Partner` interface names became
`InboundConnectorDriver`/`OutboundConnectorDriver`; Process moved under the
family-owned `connectors/process/` module without semantic movement.

### C1 — stable identity and separate catalogues

`ConnectorId`, `ConnectorDirection`, compiler `ContractCatalog` and physical
`DriverRegistry` landed. Categorical plan-package v10 carries the id and roles
and validates them without either registry.

### C2 — global role-aware binding

`RuntimeBindings::try_new` binds every runnable inbound and callable outbound
family before execution. One test family proves shared duplex state. Request
preparation, start, cancellation, scheduler completion and response polling
route by Node path through the bindings; the VM contains no Process/File
dispatch.

### C3 — `File` contract and invocation settings

`rastok/file@1` declares one-file `read` and atomic `replace`, exact ports and
portable `FileExit`. Dynamic logical paths cross source, checker, plan,
Registry-free validation and invocation evaluation as typed values. Directory
traversal, parent creation and `watch` refuse rather than approximating.

### C4 — real filesystem effect

The File Driver seals its complete operation before OUTBOUND open, then
performs a bounded all-or-nothing read or native same-directory atomic replace.
Host-specific failures project to portable terminal cases. Cancellation, late
completion and no-recall replay use the generic boundary rules.

### C5 — conformance, Lab, and static composition

One registry-backed battery proves Process and File sheet/exit shape, silence,
typed terminal coverage, correlation, journal-before-effect, close-once and
every explicitly unprovable case. Lab mock factories use the same exact ids,
roles, pure request preparation and scheduler projections; only the post-open
external interaction is scripted. A mixed Lab and its real graph have the same
semantic hash and validated plan, and both families appear as ordinary
open/closed calls in the journal.

### C6 — contribution and future discovery seam

[`connector-drivers.md`](connector-drivers.md) is the single contribution path:
Contract, Registry-free mirror where needed, pure family protocol, Driver,
factory, real conformance, Lab twin, then reduced/combined composition.

`DriverManifest` proves that canonical id/role capabilities can be inspected
without loading implementation code. It rejects duplicates and canonicalizes
entry order. It deliberately contains no factory, function pointer, artifact
locator or physical placement. Actual code must still register an ordinary
factory and pass `RuntimeBindings`; a manifest claim alone never executes.

## Static builds and plugins

Static registration is implemented and first-class. Embedded, minimal and full
standalone binaries may explicitly register different Driver sets against the
same semantic plan model. Cargo features may become presets, but they do not
replace explicit registry evidence.

The following are compatibility constraints, not shipped features:

- a future native or out-of-process loader produces ordinary registry entries;
- a sidecar/handshake may project to `DriverManifest` before code loads;
- loaded code is not trusted merely because the manifest parsed;
- the normal factory/binding checks still run;
- discovery never creates another VM, plan format or Lab model.

No serialized plugin-manifest syntax, `.so`/`.dll` ABI, Wasm component ABI,
artifact locator, trust/signing policy, process isolation, lifecycle or hot
reload contract is frozen.

## Adversarial closure pass

The 2026-08-24 pass exercised the boundaries that the happy-path closure did
not: portable File confinement, cancellation refusal before close-once,
callable-role validation, correlation-oracle soundness, complete Process-sheet
validation, and retirement of per-call caches. It also made File available in
the shipped CLI through explicit deployment data, removed the Lab's central
family-name dispatch, shared immutable mock trees, and kept request framing to
one final copy and digest. All changes are refusal, liveness, portability,
composition, or cost corrections; semantic identity, package bytes and causal
traces remain unchanged.

## Closure gates

`rastok-core --no-default-features` checks on Cortex-M33, Cortex-M3 and
RV32IMAC. The public echo Lab reports three passing scenarios.

## Named limits

- `File.watch` and directory traversal are not implemented.
- No production Inbound Driver has yet paid the acknowledgement/backpressure
  widening of the interface.
- Dynamic plugin loading and distributed Driver placement remain later
  physical Host/Worker work.
- Graph lifecycle-handler source syntax remains attached to the Loop slice.
- The catalogue beyond Process/File remains declared or guarded, not claimed.

At this historical checkpoint M1 continued with HttpClient, HttpServer
acknowledgement, Loop, cost counters and a live-view placeholder. That
placeholder was subsequently specified and delivered as M1.9 `--ui`; it is
not the distinct deferred `File.watch` contract.
