# M1.9 — independent Fable browser audit, 2026-09-07

Claude Fable 5.1 was invoked through its Chrome integration for a read-only,
blind-first audit of `ui_tour.two_tenants`. It then inspected the UI source
and specification. No repository or runtime edits were delegated. Its final
report left the audited process at LIVE, Session 3, B0.

This is an independent usability review, not a new milestone closure. The
audit used the first corrected server; the final empty-Step correction and
the local fixes below were qualified separately by the
[browser regression suite](m1.9-ux-qualification.md), not silently attributed
to Fable's pass.

## Verdict and understood model

Fable's clarity score is **6.5/10**. It correctly inferred the two keyed
inputs, the fan-out to the Process and audit scope, the timeout/retry path,
the distinction between mailbox occupancy and open instances, A/B/R,
and the scenario-driven logical clock. It confirmed those interpretations
against the DSL afterwards.

Back, the slider, record-to-boundary navigation, Return live, old sessions,
Loop runs, source Definition, pan, Fit and the splitter worked. Pause held
the displayed frame for the observed three-second interval. Loop commands
were not drawn as spatial edges; outputs disposed to `nothing` stayed local.
No console error was observed after console tracking was enabled.

Fable also reported rapid Step clicks being lost. Commands already in flight
disable further submission; no command queue is promised. Better pending-action
feedback remains useful, but accepted commands must not be conflated with clicks
on an unavailable control. Reset in history likewise requires Return live by
the current read-only navigation contract; its reason must remain accessible.

### The `advance` gap is not closed by equal histories

In the reference tour, B21 contains R18–R27: two Call closures, two timeouts,
two instance openings, two port transactions and two scheduled recurrences.
`ScenarioSession::next_action` invokes `vm.advance` as one authored action.
The result is deterministic and Step/Continue agree, but that does not make
the grouped VM work individually inspectable. This falls short of the
fine-grained stepping/lifecycle intent of `docs/spec/ui.md` section 2.

The next controller/Lab stepping design must retain real intermediate states
while preserving the same journal and logical-time semantics. The renderer
must not fabricate intermediate frames from a final snapshot. This UX pass
does not change `lab.rs`, `vm.rs`, timers or causal identities to hide the gap.

## Qualification limits and counter-checks

- Chrome reported a 1352×761 viewport for Fable's audit. The automated
  captures use the required exact 1352×760 viewport.
- Fable initially measured only one frame/s with four selected. It then
  measured `document.hidden = true` and found the same one-second clamp on
  an independent 250 ms timer. This is not evidence of a selector bug.
  The visible-page regression separately measures approximately 1,002 ms
  and 252 ms at the two selected speeds.
- Fable's window controller could not reach the narrow viewport. The
  separate 700×760 browser test covers it; no narrow visual pass is claimed
  on Fable's behalf.
- Classified scenario-source redaction was inspected in code, not exercised
  in Fable's browser because that scenario was absent from the running tour.
  The focused sensitive/personal Rust tests cover the serialization boundary.
- Global debugger keyboard shortcuts were not found. Keyboard support in
  this pass covers existing buttons, tabs, slider, badges and splitter, not
  an undocumented shortcut map.
- Fable did not review the complete Git diff line by line. Its source audit
  used read-only file tools; no shell or write access was granted.
