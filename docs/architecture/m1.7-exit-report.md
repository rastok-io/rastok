> Closed 2026-08-28. Normative authorities:
> [D-2026-08-28-1 through D-2026-08-28-8](../spec/decisions.md).
> Ordered implementation record:
> [`m1.7-loop-backlog.md`](m1.7-loop-backlog.md).

## Verdict

M1.7 answers its question positively: Rastok can express and execute finite
temporal recursion while keeping the declared topology acyclic. `Loop` is the
first executable `node::Aspect`. It wraps one Graph boundary, contributes
typed `next` and `expired` ports, and admits either a positive structural fuel
bound, a checked integer ranking proof, or both.

One external root owns one journal-derived Loop run. Every completed body
application proves exactly one progress verdict: continue through one `next`,
or terminate through one atomic transaction containing ordinary domain
outputs. Immediate and delayed progress use the same `Next`/`Admit` fold;
fuel, iteration state and pending due date are replay facts rather than RAM
authority.

```text
spatial DAG (one body application)

  Loop.in ──▶ ordinary Graph / Operators / bounded Calls ──▶ terminal output(s)
      │                           │
      │                           └────────────────────────▶ next(state')
      │                                                        │
      └────────────── l:next Admit ◀── optional dated arm ◀────┘

temporal history

  Open(root, fuel, state0)
       ├─ Next(state1) ─ Admit ─ Next(state2) ─ Admit ─ Close
       └─ final permitted Next ──────────────────────── Expired
```

No spatial back-edge is introduced. The finite-control proof follows the
whole contained flattened DAG, so ordinary nested Graphs are composition
seams rather than opaque mini-runtimes. A nested Graph carrying its own Loop
aspect remains a separate, explicitly unsupported temporal owner.

## The contract that exited

| Surface | Closed rule |
|---|---|
| carrier | one root Graph carrying `+ Loop` |
| state input | exactly one typed `in` |
| continuation | aspect-owned `next: In`, never a source edge |
| exhaustion | manager-owned `expired: LoopExpired { last_state: In }` |
| terminal result | one transaction with one or more ordinary domain outputs |
| termination witness | positive `Loop.fuel`, discharged `Loop.measure`, or both |
| delay | absent, fixed, or safely saturating exponential |
| body effects | pure Nodes plus bounded outbound Calls; a Call decides only from its exactly-once typed `exit` |
| context | immutable `Loop.state.data` and `Loop.state.meta` from the current iteration entry |

`Loop.state` is one structural binding. Exact dotted aliases and deeper member
paths resolve to the same immutable envelope, so a checked
`Loop.state.data.field` cannot fail merely because execution exposed only a
shorter spelling.

## Gate evidence

### L0–L2 — taxonomy and categorical transport

Every declaration has one structural `node::Kind`, one effective
`node::Type`, and a closed canonical aspect list. `Loop` and `Saga` are
aspects; reducer, aggregator, window, joiner, router, dispatch and fan-out are
ordinary patterns. Singular `instance` keeps key selection orthogonal to
lifetime.

Categorical v13 introduced the exact Loop boundary, closed `LoopSpec`, nested
Graph port rows and Node-or-Graph handler ownership. Registry-free validation
re-derived every contribution and refused execution until the later runtime
gate landed.

### L3 — one finite progress verdict

The core validates a finite symbolic control summary from the transported
handlers, edges, types and Connector exchange contracts. Complementary guards
and closed tagged-union cases may partition control; silence, duplicate
continuation, mixed continue/terminate and repeated terminal transactions
refuse. A bounded outbound Call may decide from its typed `exit`; its
zero-or-more data outputs cannot decide progress.

L7 extends only the walk over the already flattened plan: every edge and Node
lexically contained by the root Loop participates, including descendants of
ordinary nested Graphs. It does not invent a nested-Loop summary.

### L4–L5 — journal fold and dated admission

Envelope domain `0x05`, `LoopRunRef` domain `0x13`, transaction key 53 and
timer kind 5 form the complete manager protocol. `Open`, `Next`, `Admit`,
`Close` and `Expired` are close-once fold transitions. The final permitted
`next` publishes its selected state as `LoopExpired.last_state`; it never
opens an unbudgeted body application.

Fixed and exponential delay arm the generic dated queue. `Admit` selects
bounded routes and commits them before delivery. Equal dates retain arm order;
duplicate or stale wakeups are inert; instance Closing fences a predecessor
generation; Loop delay changes neither Call timeout nor instance lifetime.

### L6 — a small checked theorem

The first proof fragment accepts a direct signed-integer measure rooted at
iteration `data`, a positivity guard on every recurrent direct input path and
an exact positive-literal decrement. The hosted checker derives a certificate;
the deterministic `no_std` verifier derives the decrement multiset again from
the canonical handler table. Proof-only execution derives a safe body budget
`max(measure, 0) + 1`; an explicit fuel remains the deliberate cap when both
exist. Categorical v14 makes fuel-or-proof representable and refuses v13.

### L7 — public composition closure

[`loop_control.rs`](../../crates/rastok/tests/loop_control.rs) compiles ordinary
Rastok source and runs it through the public Lab surface. Its scenarios prove:

| Composition | Observable evidence |
|---|---|
| singleton + concurrent roots | two independent delayed runs open and finish in deterministic successive windows |
| keyed instances | `alice` and `bob` retry independently under one Loop Graph |
| ordinary nested Graph | a contained nested DAG executes once per body application |
| Connector retry | the first Process Call times out; Loop delay then opens a fresh bounded Call |
| Process multi-frame | two data frames may be observed for one successful Call, while only its single typed `exit` chooses the Loop verdict |
| exhaustion | public Lab observes exactly one typed `LoopExpired` |
| finite lifetime + Closing | the predecessor's delayed wake becomes stale; a clean successor generation terminates normally |

The companion negative controls reject a zero-or-more Connector output as a
progress decision and retain every named fail-closed composition below. No
scenario inspects private VM state; assertions consume public reports and
journal records.

## Named limits

- Direct `Operator + Loop` and `ConnectorType + Loop` are not v1 carriers;
  wrap ordinary work in a Graph.
- An ordinary nested Graph may contribute Nodes to the flattened body. A
  nested Graph carrying its own `Loop` aspect remains fail-closed.
- Direct spatial terminal edges to the Loop boundary and explicit Loop `stop`
  remain fail-closed until the generalized verdict/Closing hooks land.
- Fresh-Worker recovery currently reconstructs direct-body runs only. A run
  with active spatial Node/Connector obligations waits for the general
  instance and Connector recovery fold.
- The theorem checker does not yet prove affine SSA, non-trivial invariants,
  tagged-union recurrence, Connector-result progress, lexicographic/custom
  well-founded relations or nested recurrence summaries.
- `Loop.jitter` and `Saga + Loop` remain named gates.
- Multi-Worker placement consumes the same placement-neutral run and instance
  identities but is outside the one-worker M1 runtime.

At this historical checkpoint M1 continued with per-flow cost counters and a
live-view placeholder. That placeholder was subsequently specified and
delivered as M1.9 `--ui`; the gallery/demo closure remains.
