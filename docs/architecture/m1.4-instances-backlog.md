# M1.4 backlog — Node instances, keys, lifetime, and Closing

> Implementation backlog — non-normative. Rebased 2026-08-18 after
> D-2026-08-18-1 superseded the unreleased named-`partition` / `per` draft.
> The semantic authority is [instances.md](../spec/instances.md). Existing
> P0–P3 code is reusable evidence, not an accepted compatibility surface; each
> retained mechanism must pass through the gates below under the new model.

## Exit statement

M1.4 is closed when every Operator, Connector, and Graph may be a singleton
or select one canonical logical instance through `instances.key`; key and
lifetime are independent; every `var` is private to its declaring Node; the
producer journals each non-static destination address; and start, Closing,
stop, and fresh generation obey one causal lifecycle. Closing a Node instance
must preserve every admitted Connector invocation's typed `exit` and every
journal-scoped Saga obligation.

The reference runtime remains synchronous, single-process, and one-worker.
It is the degenerate physical form of the target M:N model: FIFO is per
logical address, order across addresses is unspecified, and each keyed owner
is independently shardable without changing source or causal identity.

## Invariants carried through every gate

- The logical address is `owner_path + outer-to-inner dynamic frames` using
  the one canonical encoding in identity.md. Runtime/journal instance
  references add the zero-based journal-derived generation; it is never part
  of the address or call identity.
- `instances.key` is evaluated once from the complete immutable entering
  envelope and lexical immutable values. The producer records the decision;
  replay never re-routes old traffic.
- Mailbox, derived immutable bindings, Node-local state, open calls, lifecycle,
  armed events, and cursors use the same instance reference.
- One mailbox has at most one active transaction. A `var` is readable/writable
  only in its declaring Node's handlers.
- Key, lifetime, Connector capacity, durability, and physical placement are
  separate concepts.
- Every keyed owner is a routing boundary and may map to a virtual shard
  independently of its parent. Physical facts never enter causal records.
- M1 adds no Tokio, thread pool, lock, or process boundary to manufacture
  concurrency. The three no-std targets and one-worker reference remain
  first-class.

## Gates

### R0 — normative rebase and negative space

- Record D-2026-08-18-1 and make instances.md the single authority.
- Remove named/inline `partition`, every `per` form, shared Graph `var`,
  targeted `stop`, and join `by` from the target grammar.
- Keep `instances`, `lifetime`, and future `closing` as independent common
  Node attributes. Admit no partial `closing` spelling.
- Name the unpublished P0–P3 package/body and diagnostics as superseded.

**Exit evidence:** all normative docs, WHITEPAPER, ROADMAP, and this backlog
describe one model and identify the implementation that must be realigned.

### R1 — surface, contracts, HIR, and checking

- Replace partition declarations/bindings with the common
  `instances = { key = <expr> }` attribute on Graph, Operator, and Connector.
- Add the closed `lifetime` sheet: persistent (including omission), idle,
  fixed, single_pass, and processing-time tumbling. Sliding/event-time remain
  named refusals.
- Infer one total key type after M1.3 port resolution; admit canonical scalar
  keys and recursively closed structs of canonical leaves.
- For a world-producing source, use the contract's resolved ingress-produced
  envelope type as its admission signature; do not special-case the missing
  graph input into `variant`.
- Enforce Node-local `var` visibility and keep Graph `val` lexical.
- Give every contract attribute a latest permitted evaluation site and every
  effective dynamic row its earliest actual site: boot, instance, or
  invocation (plan results remain values). Freeze the Process settings that
  may consume per-instance immutable context; no profile/port-shaping setting
  may be dynamic. Lift the existing `cwd`/`env` examples into the actual sheet
  rather than preserving documentation-only configuration.
- Remove join `by`; a join correlates inside its owning Operator instance.

**Exit evidence:** old spellings fail with one migration diagnostic; all four
key/lifetime combinations check; key expressions type-check under every
effective input; no child can resolve an ancestor `var`; a child Connector can
bind a contract-authorized setting from a parent Graph `val` exactly once.

**Checkpoint (2026-08-21):** the common positive surface, closed lifetime
sheet, four orthogonal combinations, canonical composite keys, multi-input
projection check, omission identity, and old-spelling migrations are in the
checker. Keyed persistent/idle Node policies use the private v8 bridge until
R2. The contract evaluation-site and lexical Graph-`val` bullets remain open;
therefore R1 is not yet marked complete.

### R2 — categorical transport and identity

- Rebaseline the private format categorically (replace unpublished v8 or
  allocate v9; never accept both bodies under one number).
- Transport `instance_key = [expression, inferred DataType]` and independent
  lifetime; validate without the compiler Registry.
- Transport typed owner `val` expressions and the phase of every non-constant
  effective Connector attribute; a decoder refuses a dynamic plan-shaping
  setting without consulting a Registry.
- Materialize Graph, Operator, and Connector owners in one parent-linked table;
  route rows retain their lexical Graph scope. Spatial DAG expansion must not
  erase a lifecycle/key owner.
- Adopt the exact `instance_address` and `(address, generation)` instance-ref
  sub-forms from identity.md for route, transaction, cursor, state/mailbox,
  and inter-shard records.
- Carry the enclosing Graph instance reference on every non-root `l:start`;
  address frames alone cannot recover an ancestor generation.
- Preserve v7 type/value/expression tags and keep a singleton/no-lifetime
  Graph as the semantic-hash immobility witness.
- Declare the causal trace move separately: mandatory instance references move
  every transaction trace, including the singleton witness, without implying
  a semantic graph-hash change.

**Exit evidence:** package sabotage of key/type/lifetime refuses; omission and
explicit persistent are one identity; every intentional package/hash move is
listed before re-blessing; every journal/trace move is listed separately.

### R3 — hierarchical routing, mailboxes, state, and cursors

- Evaluate the destination key before producer commit/reservation, with
  `data`, all three metadata zones (including `meta.sys`), and lexical vals.
- Select a newly entered owner chain outermost to innermost. Validate each
  owner's candidate instance bindings before a child key may consume them;
  source bootstrap fields close by boot and cannot depend on the envelope
  they produce.
- Record the full target instance reference in INBOUND/TX routes; recovery
  uses it as authority.
- Make mailbox reservation + producer route commit the admission linearization
  point. Reservation returns the instance reference sealed into the route.
  Pre-close routes retain the old generation through delayed transport;
  post-close attempts do not commit until the next generation.
- Derive entered/left owner frames from the validated owner tree and the
  route's lexical scope, never by parsing dotted paths.
- Key mailbox, Node-local state, open calls, lifecycle, timers, and consumed
  cursors by that instance reference; FIFO is per `(edge, source instance
  reference)`.
- Prove that a committed reservation consumes its generation even when the
  delivery is never polled: recovery materializes its start or Closing retires
  it with the residual delivery, and no later route may reuse the ordinal.
- Evaluate owner `val`s and instance-bound Connector settings purely into a
  candidate bundle before `l:start`; on failure, consume nothing and perform
  no adapter effect. Store successful values in the instance bundle, never as
  mutable state or envelope metadata.
- Treat every nested keyed owner as a delivery boundary even when colocated.
  Implement a stable architecture-neutral virtual-shard mapping as a pure
  proof seam while still executing on one Worker.

**Exit evidence:** nested and sibling keys never share state/cursors; rewriting
metadata after entry cannot migrate an instance; binary/temporal/enum/nested
struct keys are byte-stable on all three no-std ISAs.

### R4 — generations and lifetime profiles

- Lazily commit `l:start`; derive generation from the journal, never RAM.
- Execute persistent, idle-by-admission-silence, fixed-from-start,
  single-pass, and epoch-aligned processing-time tumbling.
- Prove a tumbling-box address has at most one forward generation; a delayed
  admitted route drains in that box and can neither reopen it nor spill into a
  later box.
- Carry generation on dated events so stale expiry is harmless.
- Journal parent/child lifecycle obligations for Graph containment and make a
  global temporal singleton a real window without a fake key.

**Exit evidence:** one start/stop pair per generation; deterministic equal-date
order; persistent arms no deadline; keyed/unkeyed lifetime matrix is covered;
re-entry after closure sees clean Node-local state.

### R5 — finite Closing, explicit stop, and call settlement

- Freeze the exact `closing = { ... }` contract before code: finite drain,
  cancellation, settlement, terminal action, and requiredness/defaults.
- Specify and implement: close external admission; continue already admitted
  internal deliveries during bounded drain; cancel in canonical call order;
  settle; publish every call's typed `exit`; run `on stop` last; reclaim.
- Use ordinary observed exits when cancellation confirms. If no outcome is
  confirmed by the settlement deadline, use the existing empty
  `OutcomeUnknown` case and close the OUTBOUND record `abandoned`.
- Graph stop cascades durably to live descendants and completes inner-first.
  R5 must freeze how nested closing budgets compose and prove one finite
  bound for the whole cascade; this rebase does not silently choose clipping,
  addition, or inherited child defaults. New arrivals wait for a clean
  generation under the existing bounded mailbox/backpressure model.
- Pending Loop wakeups die with their generation; Saga compensation debt
  survives because it is a journal fold.

**Exit evidence:** reply/timeout/stop/cancel races have one journal winner; no
frame follows a call `exit`; no lifecycle event substitutes for an exit;
residual internal deliveries are journal-visible, never silently erased.

### R6 — joins, Lab, and model checking

- Prove join correlation is exactly the owning Operator instance and that
  `where`/`within`/`last` never create another key authority.
- Add public-behavior scenarios for key isolation, nested addresses, every
  lifetime, fresh generation, and Graph close cascade.
- Model-check the bounded Closing interleavings promised by M1.3 and R5.
- Pin canonical address/frame ordering and trace projections independently.

**Exit evidence:** equivalent composite keys select one address; different
keys never share state; invalid/missing key paths refuse exactly; the Lab can
prove lifecycle and call-terminal invariants without reading private `var`s.

### R7 — closure and cluster-readiness audit

- Remove obsolete `PartitionSpec`, named-partition diagnostics, draft package
  rows, and singleton shortcuts only after their replacements are proved.
- Audit Host/Worker routing: address -> stable virtual shard -> current Worker;
  moving a shard must not change semantic hash, journal bytes, or replay.
- Sweep all docs/examples/goldens and record every deliberate identity move.
- Run fmt, clippy `-D warnings`, all-feature tests/doc, three no-std ISA builds,
  and the emulated Cortex-M33 spike.

**Exit evidence:** no active old-surface scaffolding remains; the exit statement
is demonstrated end to end on the one-worker engine and by a placement-neutral
address/shard proof.
