# Security policy

Rastok is at an early experimental stage and has no supported production
release. Security reports are nevertheless welcome.

Do not disclose a suspected vulnerability in a public issue.

The designated recipient is Yoann Pantic, through `security@rastok.com`,
with subject prefix `[RASTOK SECURITY]`. The mailbox is active; keep
sensitive details out of the subject line. When GitHub private
vulnerability reporting is offered in the repository's Security tab, it
reaches the same maintainer and may be used instead. Neither a public issue
nor a GitHub `noreply` address is a channel for sensitive details.

The remaining owner actions around these channels are tracked in the
[opening checklist](docs/architecture/github-opening-checklist.md).

Include:

- the affected revision and component;
- the conditions required to reproduce the issue;
- a minimal reproduction or trace when possible;
- the expected impact;
- whether the issue is already public.

The project will acknowledge reports on a best-effort basis. It does not
currently promise a response time, embargo period, support window, or
production security SLA. A coordinated disclosure process will be agreed
with the reporter for confirmed issues.
