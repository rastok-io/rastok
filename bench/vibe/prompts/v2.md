# Writing a Rastok graph — language card v2 (M1 surface, D-2026-08-09-1)

You are writing one `.rkg` file: a typed dataflow graph. Envelopes
(records with a `data` value) enter at the boundary, flow along
edges through operators and connectors, and leave at the boundary.
Reply with the file content only — no fences, no commentary.

## Shape

```
graph <name> : App {
  connector <name> : Process {
    mode = job ; command = "<binary>"
    args = ["-c", "..."]                  // optional
    codec = lines
    effect = idempotent ; behavior = deterministic
    timeout = duration("2s")              // optional call budget
  }

  operator <name> {
    var <name> : <type> = <init>          // persistent state, optional
    on in where <condition> {             // guard optional
      val <name> = <expr>                 // local binding, optional
      <var> = <expr>                      // state update, optional
      out = <expr>                        // the emission
    }
  }

  . -> <operator> -> <connector> -> .
}
```

## Rules that decide whether your graph is valid

- **One handler per port.** A single `on in { ... }` per operator;
  express branching inside it (guard drops, ternaries choose).
- **Emissions.** `out = <expr>` emits that value as the new `data`.
  `out = {field = <expr>, ...}` builds a record containing exactly
  those fields — it REPLACES the incoming data, nothing is merged.
  `out = data.field` extracts. `out = .` re-emits the incoming
  envelope unchanged. A handler whose guard is false emits
  nothing and the envelope stops there, silently.
- **Guards** are `where <expr>` on the handler; they may read `data`
  and the operator's `var`s.
- **State.** `var n : int = 0` (also `text`, `bool`). Assign with
  `n = <expr>` inside the handler. Statements are newline-separated,
  in order.
- **Connectors speak text.** The `lines` codec frames a text `data`
  — send `data.field` or a text expression into a connector, never a
  record. Records flow freely between the boundary and operators.
- **Budgets are declared, not implemented.** `timeout =
  duration("1s")` on the connector makes the runtime close a silent
  call with a typed `TimeoutExpired` at the error port. Never build
  timeout logic yourself.
- **Effect and behavior are mandatory** on every connector.
- **Edges.** `. -> a -> b -> .` chains boundary→a→b→boundary. For
  fan-out, name the ports explicitly, one edge per line:
  `gate.out -> archive.in` and `gate.out -> pager.in`, then
  `archive.out -> .` etc. `.` is the boundary.

## Expressions (a small CEL subset)

Field access `data.site`, index `xs[0]`; arithmetic `+ - * / %`
(integer division truncates); comparisons `== != < <= > >=`;
booleans `&& || !`; ternary `cond ? a : b` (parenthesize when
nesting); `size(<list>)`; `duration("2s")`; literals: ints, `"text"`,
`true`/`false`, lists `[1, 2]`. There are NO string functions, no
loops, no comprehensions.

## Traps

- Not available in this build: a second handler on the same port,
  `err = ...` emissions from operators, the `jsonl` codec,
  `mode = service`. Do not use them.
- `last` and `within` are reserved words — never use them as names.
- Map keys in record emissions use `=`, not `:`.
