# Writing a Rastok graph — language card v4 (categorical v19)

Write one `.rkg` file containing the requested typed dataflow graph. Reply
with file content only, without fences or commentary. Preserve the interface
names required by the task and its referee.

## Shape

```
graph app : App {
  input in: text
  output out: text

  operator relay {
    input in: text
    output out: text
    on in where size(data) > 0 { out = data }
  }
  connector shell : Process {
    command = "cat"
    codec = lines
    timeout = duration("2s")
    idempotent = true
    behavior = deterministic
  }
  in -> relay -> shell -> out
  shell.err -> nothing
  shell.exit -> nothing
}
```

## Rules

- A Graph is a scope: children, typed boundary and static wiring. Only an
  Operator has DSL handlers and private `var` state. A Connector has a Contract
  and settings, not handlers. `App` is the root Graph's Extension.
- Graph boundary names are explicit. From inside the Graph, `in` is a source,
  `out` a destination. A bare child uses its conventional `in` or `out` port.
  `. ->` and `-> .` are rejected. `out = .` remains a full-envelope emission.
- Every productible output needs a destination, including Connector `err`
  and `exit`. Use `-> nothing` to discard intentionally. A declared output
  never produced is warned about but needs no route. Nothing is exclusive:
  do not also send the same source case to a real destination.
- One handler per trigger. `on in where P { ... }` consumes false inputs
  without output. For alternatives, use ordered predicates and a fallback:
  `on in match { data > 0 => positive = data ; _ => other = data }`.
  Closed matches use `on in match data { Case => ... ; _ => ... }`.
  A match is the final dispatch, not a statement after mutation or emission.
- Statements execute in written order; the entire handler commits atomically.
  `var count: int = 0` is private state; `count = count + 1` updates it.
  `val value = expr` is a pure local binding before the dispatch.
- `out = { field = expr }` replaces DATA with that record; nothing is merged.
  `(a, b) = data` creates two ordered emissions. `source -> { a ; b }`
  instead delivers one envelope to two destinations atomically.
- Process `lines` consumes and emits text. `jsonl` carries structured input
  but its decoded frames are `variant`: narrow before structural access.
  `out` and `err` are data; exactly one typed `exit` closes each job Call.
  `TimeoutExpired` is an exit case, not text and not an implicit error sink.
  Declare a positive `timeout`; do not implement timeout scheduling yourself.
- `idempotent = true` is an explicit guarantee for repeated Calls, not a
  scheduler or an automatic retry. The retired global `effect` attribute is
  not accepted. Loop advances program state; Retry repeats the same operation
  under a static terminal-case policy. Do not invent either for these tasks.
- Join `on (a, b) where P` preserves both candidates when P is false. This is
  deliberately different from a single-port filter. Scenario `expect ... where`
  remains an assertion predicate.

## Expressions

Use fields `data.site`, list indexing `xs[0]`, arithmetic `+ - * / %`,
comparisons, booleans `&& || !`, ternary `cond ? a : b`, `size(xs)`, and
`duration("2s")`. Integer division truncates. Literal lists use `[1, 2]`;
struct fields use `=` in values and `:` in type declarations. Do not invent
functions or assume general CEL comprehensions. Use `data is Case` to narrow
tagged unions before reading case fields.

## Scope

Keep these benchmark solutions to their requested behavior. The runtime also
supports bounded Loop Extensions, HTTP and WebSocket Contracts, but none is a
substitute for the explicit ports, state and Process interface in a task.
`within` and `last` are reserved join-clause words, not variable names.
